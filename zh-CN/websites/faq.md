# Kimi Websites 常见问题

> 预览面板各按钮、编辑模式、发布与取消发布的完整操作说明，见[《Kimi Websites 网站》](/websites/websites-overview)。本页只覆盖使用中的常见问题排查。

## 预览打不开、看不到最新版本？

> 例如："网站没有显示出来""预览里还是旧版本""看不到最新保存的版本"

在绝大多数情况下，网站已成功生成并保存，「看不到」多发生在预览或版本卡片的展示环节。最常见的原因是项目目录不正确，其他情况按以下顺序处理：

<Callout type="warning">
**确认项目目录正确**：网站项目需位于 `/mnt/agents/output/app`，预览只会读取从该目录保存的版本。若 Kimi 把项目建在了其他位置（如临时目录 `/tmp`），版本会保存成功但预览取不到——可让 Kimi 将项目放到该目录后重新保存。
</Callout>

1. **刷新页面或重新打开该对话**——版本卡片有时需要几秒才会生成。
2. **在对话中让 Kimi 重新保存一次版本。**
3. **对话过长时，尝试开启新对话**（见下方「对话很长，需要开新对话吗？」）。
4. 若仍看不到：代码与版本通常已保存成功（可让 Kimi 报出版本号）。此类情况多为预览服务的临时波动，请稍后重试；如持续存在，可点击预览面板的**用户反馈**（信封图标）提交反馈并附上版本号，会有专人排查。

## 网站是空白页、白屏、崩溃，或浏览器访问异常？

> 例如："页面一片空白""网站是空的""网站崩溃了""打开后什么都没有 / 点了没反应"

- 空白或崩溃通常是**前端运行报错**（如缺少依赖、直接访问了某个子页面、个别资源或图片未加载）。可在对话中把现象描述给 Kimi（附上截图更好），让它定位并修复后重新保存版本。
- 若感觉是**文件缺失**导致的空白，网站的每个版本都保存了快照，可让 Kimi 从历史版本中恢复（见下方「项目文件、目录丢失」）。
- **浏览器兼容性**：部分注重隐私的浏览器（Brave、某些 Firefox 插件）会拦截前端资源加载，导致页面显示异常。建议将 Kimi 域名加入白名单或临时关闭 shields/隐私拦截，或换用 Chrome / Edge / Safari 访问。

## 点击「发布」失败怎么办？

处理方式与上一条相同：稍后重试；若持续失败，通过**用户反馈**提交并附上版本号即可。版本已保存成功，无需从头重做。

## 网站链接有效期是多久？会过期吗？

如果用户点击「发布」将网站公开部署，产生的网站链接将始终有效，除非手动点击「取消发布」将网站设为私密，或者内容不适触发举报。

## 网站里显示乱码、排版错乱或不适配我的设备？

- 在需求中明确说明目标设备：PC、手机、平板，或要求"响应式布局"。
- 指定浏览器兼容性要求（如支持 Chrome/Safari/Edge）。
- 若出现中文乱码，可要求 Agent 设置 UTF-8 编码。
- 复杂页面建议分模块生成，避免一次生成过多内容导致样式冲突。

## 内容、数据或记录丢失了、不见了？

> 例如："我主页的内容消失了""数据库之前上传的知识都没了""我上传的信息不见了""AI 说数据永久丢失了"

大多数情况下数据并未真正丢失，可按以下顺序确认：

1. **先确认网站是否真的是「全栈」**：只有由**后端（数据库）能力**构建的全栈网站，数据才会存到平台的云端数据库、跨访问与设备保留。实际中，很多说"做全栈"的网站 **最终只做了前端**，数据从未真正入库——这种情况下刷新或换设备自然看不到之前的数据。可让 Kimi 确认项目是否包含真实的后端与数据库。
2. **纯前端网站**：数据只保存在你当前使用的浏览器本地（localStorage），换浏览器 / 换设备、或清理浏览器数据都会丢失。需要长期、多设备保留数据，请让 Kimi 改用带数据库的全栈方案。
3. **确属全栈网站**：数据保存在平台托管的云端数据库中，**发布新版本不会清空已有数据**；若确是全栈却看不到数据，多为临时问题，请刷新或稍后重试。
4. **若确认数据确实丢失**：请点击预览面板的**用户反馈**（信封图标）提交反馈，会有专人检查处理；此时不要继续反复操作，以免覆盖。

## 项目文件、目录丢失，或提示「环境被重置」「无法恢复」？

> 例如："我的网站项目目录没了，无法恢复""文件不见了""提示环境被重置了"

- 网站的**每个版本都会保存快照**，源代码通常可以从历史版本恢复。可让 Kimi 列出历史版本，并回退 / 恢复到指定版本。
- 若发生在**很长的对话**中（尤其中途切换过模型），建议开启新对话（见下一条）。
- 仍无法恢复时，点击**用户反馈**提交，会有专人排查。

## 对话很长，需要开新对话吗？

若一个对话持续很久、跨越了很多个版本，或中途切换过模型（如 K2.6 → K3），可能导致当前使用的能力不是最新版本，从而出现上下文丢失、文件异常等问题。**这种情况建议开启新对话重新开始**，以获得最新的构建与交付能力；已发布的网站与历史版本不受影响，仍可正常访问。

## 导出代码后能自主部署吗？

可以打包下载完整项目代码部署到自己的服务器，但以下两项由 Kimi 平台提供，**不会随代码一同迁移**：

- **Kimi 账号登录**：属于平台提供的登录能力，离开 Kimi 平台后无法直接使用。自主部署若需要登录，请让 Kimi 基于自有数据库实现账号密码登录系统。
- **平台托管数据库**：全栈网站的数据保存在平台为该站点分配的云端数据库中，导出的代码不包含这份数据，也不会自动连接到你自己的数据库；自主部署需自备数据库并迁移数据。

若只是希望网页公开可访问，直接使用平台的**分享 → 发布**即可，无需自建服务器，Kimi 账号登录与云端数据也将继续正常工作。

## 生成的网站内容和我的要求不一致怎么办？

- 在对话中具体指出哪里不符合：例如颜色、布局、文字、功能模块、数据表格等。
- 可上传参考图片、示例网页或更详细的文字描述，让 Agent 按参考修改。
- 若多次修改仍不满意，可尝试新建一个对话，用更结构化的需求重新生成。

## 生成后还能修改网站内容、链接或样式吗？

可以。在原对话中继续告诉 Agent 你想修改的内容，例如：

- "把首页标题改成 XXX"
- "把'联系我们'按钮的跳转链接改成 https://xxx"
- "整体换成深色主题"

修改后 Agent 会重新生成并部署新的链接。

## 如何给网站添加后台、数据库、登录功能？

- 在建站指令中强调，生成带有数据库、登录功能的全栈网页。
- 也可以让 Agent 先生成前端页面，再将源码导出后交给开发者二次开发。

## 可以下载网站源码或导出到 GitHub 吗？

当前版本支持在对话中，打开全部文件，点击下载按钮，你可以把所有文件下载到本地。

## 生成/修改一个网站会消耗多少额度？

网站生成属于复杂任务，通常会消耗较多 Token/额度，具体取决于：

- 页面数量和复杂程度
- 是否包含图片、表格、交互逻辑
- 迭代修改次数

建议在需求描述中尽量清晰，减少反复试错；若对结果不满意，可在反馈中说明情况。

## 生成网站时很慢、一直排队或终端运行失败？

- 高峰期（工作日白天、晚间）可能出现排队，建议错峰使用。
- 若任务卡住超过 10 分钟，可尝试先刷新网页。
- 复杂网站建议拆分为多个小任务：先出首页，再逐步添加子页面和功能。

## Kimi 的网站生成适合做什么？不适合做什么？

**适合：**

- 个人主页/作品集、活动落地页、产品展示页、简单工具页、小游戏原型
- 快速验证设计想法、生成可交互 demo
- 需要简单后端数据库、用户系统的网站

**不适合：**

- 支付系统的复杂网站
- 高并发、高可用的正式生产环境
- 需要长期稳定托管且绑定自有域名的业务站点
